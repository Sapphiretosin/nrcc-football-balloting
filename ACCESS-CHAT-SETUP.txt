NRCC MATCHDAY ACCESS + CHAT SETUP
===================================

Branch: matchday-access-chat
Existing live site is NOT changed by this branch until you deploy it.

FEATURES IN THIS BUILD
- Public match chat requires a signed-in account.
- Visitors can create public accounts; this does not grant manager access.
- APJ and PFO private manager rooms.
- Manager role registry with four intended slots (two APJ, two PFO).
- Super Admin manager-login dashboard.
- Main scoreboard controls remain Super Admin-only.
- Successful manager sign-ins are recorded in managerLoginAudit.
- Firestore rules are supplied separately in firestore.rules.

IMPORTANT SETUP BEFORE DEPLOYMENT
1. In Firebase Console, open Authentication > Sign-in method and enable Email/Password.
2. Open Firestore Database > Rules and replace the rules with the contents of firestore.rules. Review them before publishing. These rules intentionally restrict all match edits to the existing Super Admin UID.
3. Create the four manager accounts in Firebase Authentication (email/password) when ready. Do not share passwords with the developer.
4. For each manager, copy the Firebase Authentication UID and create a Firestore document in collection managerRoles with the UID as document ID. Fields:
   - team: "apj" or "pfo"
   - displayName: manager's display name
   - email: same email as the Authentication account
   - active: true
   Only the configured Super Admin can write managerRoles under the rules.
5. The existing ADMIN_UID in index.html is Lgn7v7G0d3UdivdoTTYp0VbdpMg2. Ensure this is the intended Super Admin account and that the Firebase security rules in the Console match it.
6. Deploy the branch's site files to Netlify only after Firebase rules are published. Keep a copy of the current live site before replacing it.
7. Test: public sign-up/sign-in and public chat; APJ manager can read/write APJ room but not PFO; PFO manager can read/write PFO but not APJ; public user cannot read either private room; only Super Admin can change match score, events, squads, awards, or manager roles.

AUDIT LIMITATION
This records successful sign-ins when an approved manager's role document is read by the client. It does not provide a complete failed-login/unauthorised-attempt audit. For that, configure Firebase Authentication/Google Cloud Logging or a trusted backend. Login events recorded from the browser are useful app telemetry, not a tamper-proof forensic audit.

CURRENT STATUS
